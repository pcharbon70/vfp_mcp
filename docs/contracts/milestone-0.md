# Milestone 0 Contract

This contract defines the observable results, required evidence, and hard scope
boundary for the codec and acceptance spike. The implementation plan is under
`.spec/planning/00-codec-and-acceptance-spike`; this document states the
executable contract and does not claim the milestone is complete.

## Required outcomes

| Outcome | Observable result | Required evidence |
|---|---|---|
| Physical codec | A bounded DBF/FPT physical model retaining raw bytes and offsets | Golden, malformed-input, property, determinism, and byte-fidelity tests |
| Semantic model | Properties, named methods, object paths, containment, and stable findings | Semantic integration tests with physical provenance and untouched-byte assertions |
| Native fixtures | Independently authored synthetic VFP 6 and VFP 9 SCX/SCT and VCX/VCT pairs | Automated inventory, cryptographic hashes, and human review signoff |
| Targeted edit spike | Pure property and named-method plans with exact DBF patches and FPT appends | Success/rejection matrices, postcondition reparse, and exact byte-footprint proof |
| Native acceptance | Recorded behavior of both targeted edit classes in their originating VFP versions | Hash-bound JSON plus Markdown signoff for open, inspect, save, reopen, and compile actions |

Self-reparse is necessary automated evidence, but it never substitutes for a
version-native VFP acceptance record.

## Excluded capabilities

Milestone 0 does not expose or implement:

- MCP tools or tool registration;
- production locks, writers, backups, journals, pair replacement, or rollback;
- structural record insertion, deletion, packing, rename, or reparenting;
- VFP IDE automation, VFP source execution, or VFP source compilation by the server;
- application data, DBC, DBF, connection, executable, deployment, or backup access; or
- changes to an original LecoWin2 or SBT source tree.

The OTP application therefore has no server or writer child during Milestone 0.
Pure codec and planning modules are libraries exercised directly by tests.

## Development source classes

| Source class | Permitted location | Permitted use |
|---|---|---|
| Generated bytes | In memory | All automated codec and malformed-input tests |
| Committed synthetic fixture | `test/fixtures/vfp6` or `test/fixtures/vfp9` | Read, parse, copy to disposable workspace |
| Disposable copy | An explicitly configured test temporary root or `.vfp_mcp/test-work` | Mutation-spike materialization and comparison |
| Raw intake | `.vfp_mcp/intake` or `.vfp_mcp/fixture-drop` | Quarantined inventory only; never execute, compile, or use as a mutation target |
| Original application source | Outside this repository | No development or automated-test access |

Relative paths are resolved against the repository workspace. A sibling-prefix
path, traversal path, absolute external path, raw intake kind, or unknown source
kind is rejected before the caller opens or acts on it. The Phase 1 guard is a
development policy; the deployed server's canonical and link-aware root policy
is implemented separately in the read-only server milestone.

## Boundary examples

- `test/fixtures/vfp9/basic_form.scx` as `:committed_fixture` is permitted.
- `.vfp_mcp/test-work/case-1/basic_form.scx` as `:disposable_copy` is permitted.
- Generated DBF/FPT binaries have no path and are permitted as `:generated`.
- `.vfp_mcp/fixture-drop/vfp9/basic_form.scx` as `:raw_intake` is rejected for execution or mutation.
- `../LecoWin2/forms/example.scx`, `../sbt/source/example.scx`, and every other external path are rejected as test sources.

Tests must use the repository-configured isolation policy and must not infer
authorization from a file's name, extension, or mere availability on the host.
