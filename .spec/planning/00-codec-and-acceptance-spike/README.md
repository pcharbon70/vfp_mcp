# Milestone 0: Codec and Acceptance Spike

## Purpose

Turn the architecture's Milestone 0 into an ordered implementation program that
proves the physical codec, semantic model, narrow edit planning, byte fidelity,
and version-native VFP acceptance before MCP or production writing begins.

## Architectural Contract

This stream implements only
[Milestone 0](../../../docs/architecture.md#milestone-0-codec-and-acceptance-spike).
The governing current-truth subjects are the
[codec specification](../../specs/codec.spec.md),
[acceptance specification](../../specs/acceptance.spec.md), and the portions of
the [mutation specification](../../specs/mutation.spec.md) needed to define a
pure edit-plan spike. The durable decisions are:

- [Own a Custom Visual FoxPro Source Codec](../../decisions/vfp_mcp.custom_vfp_codec.md)
- [Constrain Source Access and Fixture Intake](../../decisions/vfp_mcp.source_access_boundary.md)
- [Gate Capabilities Through Versioned Milestones](../../decisions/vfp_mcp.versioned_capability_rollout.md)
- [Serialize Guarded Pair Transactions](../../decisions/vfp_mcp.guarded_pair_transactions.md), as a later-milestone boundary only

Milestone 0 does not expose MCP tools or implement production locking, backup,
journaling, rollback, pair replacement, or structural editing.

## Research Baseline

Implementation uses the repository's
[architecture and format research](../../../docs/research/architecture-and-format-research.md),
[progress record](../../../docs/research/progress-to-date.md),
[fixture intake investigation](../../../docs/research/fixture-intake-investigation.md),
[component design](../../../docs/components.md), and
[fixture authoring checklist](../../../docs/testing/fixture-authoring-checklist.md).
Research is input to implementation and does not replace executable or native
acceptance evidence.

## Minimum Result

Milestone 0 produces:

- a deterministic, bounds-checked DBF/FPT parser retaining physical provenance;
- a conservative semantic model for SCX/SCT and VCX/VCT pairs;
- independently authored and reviewed synthetic VFP6 and VFP9 fixture pairs;
- pure property and named-method edit plans with exact byte footprints;
- hash-bound machine-readable and human-reviewed native acceptance evidence;
- an explicit `accept`, `revise`, or `stop` decision for Milestone 1.

## Included Scope

- DBF headers, descriptors, records, deletion markers, and memo pointers.
- FPT headers, block sizes, block headers, alignment, and bounded payloads.
- Explicit encoding and raw-byte preservation.
- Properties, named methods, hierarchy paths, containment, and findings.
- Synthetic VFP6 and VFP9 forms and class libraries.
- Pure in-memory edit planning and materialization on disposable copies.
- Human-operated native open, inspect, save, reopen, and compile acceptance.

## Excluded Scope

- MCP protocol handlers or user-facing tools.
- Production filesystem writer, locks, backups, journals, rollback, or recovery.
- Edits to original LecoWin2 or SBT source trees.
- Access to application data, DBCs, connections, executables, or deployments.
- Automated control of the VFP IDE.
- Record insertion, deletion, packing, reparenting, or other structural edits.

## Status and Evidence Rules

All phases begin `Planned`. Checkboxes remain unchecked until the named result
and proof exist. Phase evidence must name commands, test files, fixture hashes,
or admitted native evidence records. A plan link or self-reparse is not proof.

Raw intake pairs remain ignored, local, read-only, uncommitted, and unexecuted.
All automated mutation tests use generated bytes, committed synthetic fixtures,
or disposable copies inside an approved isolated location.

## Dependency Graph

```text
Phase 1 -> Phase 2 -> Phase 3 -> Phase 4 -> Phase 5 -> Phase 6
                          ^          ^
                          |          |
                    fixture model   admitted corpus
```

Phase 4 may begin its human logistics after Phase 1, but fixture promotion and
golden semantic manifests depend on the Phase 3 model. Phase 5 may use generated
vectors before Phase 4 completes, but its phase gate requires admitted fixtures.

## Roadmap Completion Gate

Milestone 0 is complete only when all six phases are complete and the evidence
shows:

- reviewed version-native VFP6 and VFP9 synthetic fixtures;
- reproducible codec, malformed-input, encoding, hierarchy, and determinism tests;
- exact byte-fidelity and edit-footprint proof;
- native findings for property and named-method edits in both VFP versions;
- resolved or explicitly constrained timestamp, `OBJCODE`, and record-order behavior;
- no access to or execution against an original application tree; and
- an `accept` decision identifying the constraints carried into Milestone 1.

An outcome of `revise` or `stop` closes the investigation record but does not
authorize Milestone 1.

## Maintenance Rules

- Keep phase numbering stable and add amendments without silently changing
  completed acceptance criteria.
- Update this index when a phase status changes.
- Keep requirement mappings in each phase's `Connections` section current.
- Store native evidence under a repository-owned evidence location selected in
  Phase 1; never embed proprietary source bodies in evidence.
- Update current-truth specs only when behavior or policy changes, and add real
  verification targets only after their evidence exists.
