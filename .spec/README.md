## Canonical Layout

- `README.md` (authored)
- `AGENTS.md` (authored, local operating guidance for agents working in this folder)
- `decisions/README.md` (authored ADR guidance for this workspace)
- `decisions/*.md` (authored durable cross-cutting ADRs)
- `planning/README.md` (authored planning index and conventions)
- `planning/NN-*/README.md` (authored milestone implementation-plan contract)
- `planning/NN-*/phase-NN-*.md` (authored phase, section, task, and subtask plans)
- `specs/spec_system.spec.md` (authored, meta-spec for this folder)
- `specs/package.spec.md` (authored, package-level intent)
- `specs/*.spec.md` (authored subject specs)
- `state.json` (generated by `mix spec.index` and `mix spec.validate`)

## Current Truth and Plans

Files under `specs/` state required current behavior and policy. ADRs under
`decisions/` record durable cross-cutting choices. Files under `planning/`
describe intended implementation work and do not prove that behavior exists.

A planned task becomes evidence only after its implementation and independent
verification are complete and the applicable subject spec is updated with a
real verification target. Status labels and checkboxes in a plan are navigation
and coordination aids, not SpecLed verification.

## Core Loop

1. if you are entering the repo or handing work to an agent, run `mix spec.prime --base HEAD`
2. make the smallest code, docs, or test change that moves the behavior
3. add or tighten the smallest proof when behavior changed
4. run `mix spec.next`
5. if it says `needs subject updates`, update the right current-truth subject in `specs/`
6. if it says `needs decision update`, add or revise an ADR only when the change is cross-cutting and durable
7. when it says `ready for check`, run `mix spec.check --base ...`
8. use `mix spec.status` when you need coverage or frontier summaries

When implementing a milestone plan, also update its phase status and completion
evidence links in the same change that supplies the evidence. Never mark a phase
complete based only on compilation, stubs, self-reparse, or an unchecked native
acceptance requirement.
